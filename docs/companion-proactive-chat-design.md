# 伙伴主动私聊

## 用户入口

在「伙伴设置 → 自动化」新建例行任务，选一次性触发，填写已约定的跟进事项和时间，将投递设为「主动发一条伙伴私聊」。选择这种投递时自动关闭运行开关并选用独立会话与伙伴模型。核对内容与时间再显式启用。上海时间 22:00–08:00 静默，每天最多两条且相隔至少三小时。超过一小时的事件跳过。运行历史分别记录生成和投递。历史只说明消息已保存进原生对话。

## 复用与缺口

- `apps/desktop/src/main/routines/service.ts` 已按伙伴校验主力电脑，创建独立的例行任务会话，并把执行结果与投递回执分开。独立会话继承伙伴资料、记忆和权限。此功能的有效路由必须固定为该伙伴当前获准的本机主路由，拒绝远端或备用路径。
- `apps/desktop/src/main/routines/delivery.ts` 的 `companion/direct` 已能写入伙伴原生聊天的 assistant 消息，附带自动化来源和基于运行 ID 的去重键。它尚不能提供跨运行事件去重、按伙伴限额、发送前重新检查聊天活动，也没有针对主动私聊的来源说明。
- `botDirectMessageService.ts` 的 `sendToUser` 是群聊授权专用，不能把群聊权限当成自动化授权。一次性首迎的 `requireNoUserMessage` 也不适合已有聊天。

## 接线顺序

1. 首版输入只接主力宿主可核实的事件。用户明确约定且到期的跟进优先。当天已确认安排和生活分享扩展时使用结构化事件，按来源 ID 加事件类型形成稳定键。单凭当前时间、聊天沉默或计划记录推不出用户正在做什么。事件超过一小时失效，不在休眠恢复后排队补发。
2. 在启动模型之前运行本地准入。确认明确开关、主力电脑、事件新鲜、主会话空闲、账户归属、当天配额和三小时间隔。按伙伴持久化领取事件，通过原子状态变更限制并发。生成失败保留失败状态，领取过的事件不重新生成；投递遇到暂时性失败只允许使用原稿与同一个事件键重试。
3. 在独立例行任务会话生成一条短消息或选择静默。限制生成使用相同伙伴授权的个人路线，不执行外部发送、待办或学习写入。生成后重新核对主力身份、开关、会话和消息版本，用户已接话或伙伴开始生成时放弃这次投递。
4. 在主聊天共享的接收边界重新判定并提交，用同一宿主事务约束稳定消息键、按伙伴日配额和确认发布。模型或队列成功不记作已投递。提交失败期间保持原稿与失败回执；重试若发现消息已提交直接回读原回执。离线、换主力和关闭开关均在提交前重新裁决。针对已有引擎会话后续接话，还需要确认模型上下文能看到这条原生主动消息，优先复用产品已有的外部可见消息恢复机制。
5. 共用 host 盖章的来源字段生成 UI 来源与上下文重建说明。保留自动化原有直接投递和普通完成通知。主动私聊设置应与宿主受控操作同权发现，生产接入前先验证 Mac 原生消息列表、刷新留存、用户后续接话及跨端回显。

## 实施和验证

当前入口使用真实的一次性例行任务触发，不推断用户事件。模型路线仅支持本机 Pi 的 OpenAI 订阅 GPT-6.2 Sol，使用独立会话、文本专用轮次，沿用伙伴资料及记忆。宿主在付费派发前校验路由。事件原子认领、原稿和消息去重键保存在宿主；一次触发只生成一次，含提交失败的事件不自动补发。已发布的消息是限额来源。主聊提交使用现有发送锁与受保护的消息写入。用户发言、会话变更或禁用会阻止投递。近期主动消息作为标注来源的既有助手上下文进入普通发送装配，保留原用户正文，注入使用既有去重逻辑。

后台测试使用原生 RoutineEngine、磁盘认领和上下文片段，生成和发布是明确的夹具。生产窗口、账号、聊天发送和模型调用没有参与该测试。上线前仍需针对测试账号验收原生列表持久显示、刷新、Pi 的下一轮接话、重启及主力电脑切换。实际启用前另行明确发送文案与次数。
