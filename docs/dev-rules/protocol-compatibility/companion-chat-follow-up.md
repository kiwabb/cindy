# 伙伴主聊天的一次性跟进

在主力电脑打开「伙伴设置 → 自动化 → 安排一次聊天跟进」，填写一个事项和上海日期时间。保存后，伙伴的自动化列表显示这一次安排。用户可以关闭待执行的安排。取消后可以另建一条。

首版只处理用户明确安排的一次跟进。默认没有任何安排。上海时间 22:00 至次日 08:00 静默，同一伙伴每天最多发布两条，间隔至少三小时。主聊天忙、刚有用户输入、无法确认主力电脑、路由不可用或超过一小时均跳过。没有补发队列，已认领后进程退出也不会重新生成。

## 运行链

- 入口采用现行 Desktop Scheduler 和伙伴项目的自动化列表。创建通过可信桌面设置 IPC，记录保存在主力电脑的调度库。工作区里的项目配置、Agent 可写的普通调度和脚本不能授予主聊天发送权。用户需要在该电脑的设置里明确安排。
- 发前重新读取有效的主聊天、档案版本、当前模型路由和输入状态。只使用该聊天已明确选定、且本机目录允许发起纯文本请求的提供方和模型。模型收到现行角色、用户资料、约定事项和有限的近期主聊天。生成不启动 Agent 或工具，也不从日程文件推断已发生的事。原生续聊继续按伙伴现有设置读取记忆。
- 投递用主聊天的发送锁和原生消息发布接口，写入带自动化来源的 assistant 行。失败时不会用任务结果冒充聊天消息。持久化的认领与实际发布时间用于去重和频率限制。主力交接前后尚未投递的安排留在原机，由原机规则跳过。该版不会迁移未触发的安排。
- 本机和 Device Link 复用现有消息更新。已有聊天云镜像可读取已发布的伙伴原文，当前镜像协议只携带作者、正文等基础信息，独立云端视图中的自动化徽标不在本次协议改动范围内。
- 后续人工回复带上近期的跟进记录作为历史助理上下文，原始用户正文按正常路径落库。重启和引擎上下文重建可从聊天记录重新读入近期跟进。清理或回退的记录不会再次进入这段说明。

## 启用与降级

代码审查和离线用例通过后，由维护者按正常发布流程安装支持此迁移的客户端。每个伙伴仍需由用户在设置里单独创建安排。降级前应在支持此功能的客户端取消待执行安排。共享数据库的版本检查及正常备份恢复流程继续适用。SQLite 迁移只新增一个可空列。
