# 学习页与导师对话的「今天」

> **状态**：fork（kiwabb/cindy）专有产品规则，2026-11-13。依据：主人确认的设计简报与定稿原型
> （2026-11-12「学习页面与待办打通」）。

导师伙伴在自己项目的 `workspace/goals/` 里用状态脚本维护学习目标。Cindy 只读这些文件，把目标、
大纲和每天的进度显示出来；修改目标、大纲、画像，出题作答，都仍在导师对话里进行。

## 入口

- 左侧导航一级入口「学习」（`/bots/learning`，`features/learning/LearningView.tsx`），与「待办」并列，
  可在自定义里移动或收进「更多」。
- 导师对话右侧的「今天」页签（`learning-today`）：只在**这台电脑上**、绑定了**进行中**目标的对话里
  自动加上（按 Session id 绑定，取自 `sessions.json`），不抢焦点、不自动展开右侧栏；本次运行里关掉后
  不再自动加回，下次启动再出现。远程或归属未定的对话不显示内容。不进「+」菜单。

## 学习页

- **今天**：每个进行中、还有未过关知识点的目标一张卡片：模块与当前知识点、学到哪一步（有题开着为
  「练习」，否则「讲解」）、待回答的题、今天到期复习数、下次复习日期、「去学习」。四段时间条只在导师
  写了 `daily_plan` 时显示，不从文字里推算。
- **目标**：每个进行中的目标一张卡片：名称、目标原话、大纲是否定稿（没有 `agreement.json` 即未定稿，
  给「去定稿」）、已掌握数／总数与进度条、最近活动。展开后是大纲（按模块，五种状态：未开始、进行中、
  已掌握、已暂缓、自述掌握；导师标了 `assessment_limits` 的知识点带「需音频／需开口说 · 暂不能检验」）、
  「关于你」（只读，提示在对话里告诉导师）、复习排期、打开导师对话。
- **已归档**：折叠列表，只读，显示已掌握数。
- **空状态**：没有进行中的目标时，说明在导师对话里开始，按钮打开导师。
- 按钮上的「导师」用伙伴自己的名字；跳转对话走统一的 `resolveSessionRoute`。

## 「今天」页签

当前知识点与所属模块、开着的题（只有题面与选项，不含答案）、今天的作答与答对次数、折叠大纲（当前模块
展开、当前位置高亮），底部三句快捷话「继续学习／先讲讲／换一道题」：目前**只写进这场对话的输入框，由用户
按发送**；没有题开着时「换一道题」置灰。设计简报写的是点了就发出：直接发送的通道
（`SessionQuickSendProvider`）只在对话消息区内可用，右侧栏拿不到，接通要改上游对话视图并按
[消息来源](message-source.md)标注来源，所以暂按预填实现，**是否改成直接发送待主人决定**。

## 数据与边界

- 主进程 `apps/desktop/src/main/learning/` 扫描本账号各伙伴的 `workspace/goals/`，只读、不跟随符号链接、
  单文件上限 8 MB；读到写了一半的文件时保留该目标上一次读到的内容。投影是白名单：不传答案、讲解、
  资料文件路径和目标徽记。掌握判定沿用导师状态脚本的口径。
- IPC `learning:snapshot` 只给本机受信界面，拒绝 device-link；目标目录变化后推 `learning:changed`。
  手机与远程控制端不读学习目标。导师的主力电脑不在本机时，这台电脑上看不到它的目标。
- 存储仍是导师的 JSON 文件，不进数据库。

## 不做

页面上修改目标／大纲／画像、页面上出题作答、复习模式、定时顺延待办。
